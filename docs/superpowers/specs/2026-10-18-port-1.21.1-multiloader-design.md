# JMT-MCMT port to Minecraft 1.21.1 (NeoForge + Fabric) — design

Date: 2026-10-18
Status: approved by the maintainer (ben001109)

## 1. Goal

Port JMT-MCMT, a server-side multithreading mod last maintained for Forge
1.18.2, to Minecraft 1.21.1 with support for both NeoForge and Fabric, then
use that branch as the base for porting to other Minecraft versions (newer and
older).

Non-goals for this spec:

- Porting to any version other than 1.21.1 (later specs).
- Client-side features. The mod stays server-side; vanilla clients can connect.
- Copying code from GPL-licensed derivatives (MCMTFabric, Async). They are
  consulted only to learn which methods need hooks. The project stays
  BSD-2-Clause.

## 2. Why a rewrite rather than a bump

The 1.18 branch hooks into Minecraft through two Forge-only mechanisms:

1. Ten JavaScript coremods under `forge-mod/src/main/resources/trans/` that
   edit bytecode with the Forge `ASMAPI`. Fabric has no coremod system and
   NeoForge 1.21 dropped JS coremods.
2. The `sync-fu` subproject, a ModLauncher `ITransformationService` that uses
   `sun.misc.Unsafe` to restart the launcher with a custom module class loader
   so it can swap fastutil collections inside vanilla classes.

Both are replaced by Mixins, which work identically on both loaders. The
Java-side logic (thread pool, SerDes filters, chunk lock, concurrent
collections, commands, config) is kept and adapted.

## 4. Core module (`common`)

### 4.1 `ParallelProcessor` (replaces `ASMHookTerminator`)

Responsibilities, carried over unchanged in behaviour:

- Owns the `ForkJoinPool` sized by `MCMTConfig.getParallelism()`; worker
  threads are named `MCMT-Pool-Thread-N`, registered in the thread tracker and
  given the mod class loader as context class loader.
- `preTick(server)` creates the per-tick `Phaser`; `postTick(server)` waits for
  all registered tasks, then drains `PostExecutePool`.
- `callTick(level)`, `callEntityTick(entity, level)`,
  `callBlockEntityTick(ticker, level)`, `callTickEnvironment(level, chunk,
  randomTickSpeed)`: each checks the relevant disable flag, registers on the
  phaser, and submits the work to the pool, running it through the SerDes
  filter when one applies.
- Statistics counters and the `opsTracing` task list used by `/mcmt stats` and
  the crash report section.
- `isThreadPooled(poolName, thread)` and `serverExecutionThreadPatch(server)`
  so pool threads are accepted where vanilla checks for the server thread.

Removed: the Forge `EventListenerHelper` hack that re-dispatched
`WorldTickEvent` listeners in parallel. Replaced by a single call to
`PlatformHooks.onLevelPostTick(level)` after each level tick, executed on the
same pool thread as the level tick. Modders who need their post-tick listener
to run on the server thread can disable world parallelism, as before.

Defensive behaviour: if `preTick` sees a phaser already present (a second
server instance), or a hook runs before the pool exists, the hook logs a
warning once and runs the work inline on the calling thread.

### 4.2 Carried over with import and name changes only

- `serdes/` (registry, `ISerDesHookType`, `SerDesHookTypes`, filters: Auto,
  GenericConfig, Legacy, Piston, Vanilla; pools: ChunkLock, PostExecute,
  SingleExecution).
- `paralelised/` (`ChunkLock`, `ConcurrentDoublyLinkedList`,
  `ConcurrentLinkedList`, `RunnableManagedBlocker`, `pooling/`, `fastutil/`).
  The package keeps its historical spelling to minimise diff noise.
- `asmdest/ConcurrentCollections` moves to `org.jmt.mcmt.util`.
- `commands/` (`ConfigCommand`, `StatsCommand`, `DebugCommands`). Brigadier
  trees are built in `common`; registration is done by each loader.
- `DebugHookTerminator` is kept only if its hooks are reimplemented; otherwise
  dropped in phase 1 and noted in the changelog.

Removed entirely: `sync-fu/`, `asmdest/PatchHookTerminator` (already empty),
`etc/buildscripts/`, `META-INF/coremods.json`, all `trans/*.js`,
`accesstransformer.cfg` (replaced by an access widener in `common` that the
NeoForge build converts to an AT, or by `@Accessor`/`@Invoker` Mixins; chosen
in phase 1).

### 4.3 Configuration

`common` defines `MCMTConfig`, a plain Java object holding the same fields as
today's `GeneralConfig` (disabled, paraMax, paraMaxMode, disableWorld,
disableWorldPostTick, disableMultiChunk, disableEntity, disableTileEntity,
chunkLockModded, te white/black lists, disableEnvironment,
disableChunkProvider, debug flags, opsTracing, logcap). It also keeps the
`bake()` / `save()` split between startup config and running config so the
`/mcmt config` commands keep working.

Each loader supplies the storage:

- NeoForge: `ModConfigSpec` (COMMON type), same keys as the 1.18 TOML so old
  config files still load.
- Fabric: night-config (core + toml) bundled into the jar with Loom `include`,
  reading and writing `config/jmt_mcmt-common.toml` with the same keys as the
  NeoForge spec. No other external dependency.

`SerDesConfig` (filter/pool definitions in `config/jmt_mcmt/*.toml`) stays
loader-independent and is reused as is.

### 4.4 Platform abstraction

`org.jmt.mcmt.platform.PlatformHooks` is an interface with one implementation
per loader, found through `java.util.ServiceLoader`:

- `onLevelPostTick(ServerLevel)`: fire the loader's level post-tick event.
- `isDevelopmentEnvironment()`.
- `getConfigDirectory()`.
- `registerCrashReportSection(String name, Supplier<String>)`.

Anything else that differs between loaders is kept in the loader module, not
behind the interface.

## 5. Mixins (replace the ten coremods)

All Mixins live in `common` and target MojMap names. Each Mixin is small and
delegates immediately to `ParallelProcessor`.

| 1.18 coremod | 1.21.1 Mixin | Technique |
|---|---|---|
| `worldparallel` | `MinecraftServerMixin` on `tickChildren(BooleanSupplier)` | `@Inject` at the start of the level loop → `preTick`; `@Redirect` the `ServerLevel.tick(BooleanSupplier)` call → `callTick`; `@Inject` after the loop → `postTick`. Injection points are located with `@At("INVOKE")` on the profiler `push("levels")` / `popPush("connection")` calls, mirroring the LDC search in the old script. |
| `entityparallel` | `ServerLevelMixin` on `tickNonPassenger(Entity)` | `@Redirect` the `Entity.tick()` call → `callEntityTick`. |
| `teparallel` | `LevelMixin` on `tickBlockEntities()` | `@Redirect` the `TickingBlockEntity.tick()` call → `callBlockEntityTick`. |
| `envparallel` | `ServerChunkCacheMixin` on `tickChunks()` | `@Redirect` the `ServerLevel.tickChunk(LevelChunk, int)` call → `callTickEnvironment`. |
| `etpparallel` | `MinecraftServerMixin` | `@Inject` at `RETURN` of `shouldRun`/`pollTask` equivalents so a pooled thread is treated like the server thread (`serverExecutionThreadPatch`). Exact target chosen after reading the 1.21.1 `BlockableEventLoop` / `ReentrantBlockableEventLoop` sources. |
| `chunkparallel`, `pscp`, `scpcoaccess` | `ServerChunkCacheMixin` | Replace the `ParaServerChunkProvider` subclass with a Mixin that adds the chunk cache fields and overrides the behaviour of `getChunk` / `getChunkNow`: `@Inject(cancellable = true)` at `HEAD` for the cache lookup and the "run on main thread if pooled" redirect; the vanilla `Thread.currentThread() != mainThread` check is relaxed with a `@Redirect` so pooled threads pass. `UtilMixin` registers the `Util` background pool threads in the thread tracker. |
| `generalparallel` | `SynchronisePlugin` (`IMixinConfigPlugin`) | In `postApply`, add `ACC_SYNCHRONIZED` to methods listed in a bundled `synchronise.json`, keyed by class and method descriptor. Avoids one Mixin class per method. |
| `gen2parallel` | `ClassInstanceMultiMapMixin` | `@Redirect` the `Lists.newArrayList()` / `Maps.newHashMap()` calls in the constructor to concurrent implementations. |

The old `varreplace.js` and `gen3parallel.js` were already dead code and are
not ported. Collection replacement previously done by `sync-fu`
(`FastUtilTransformerService`) is ported in phase 4 as targeted `@Redirect`s
on constructors of the affected vanilla classes, one Mixin per class, using the
existing `paralelised/fastutil` wrapper classes.

## 6. Loader modules

### `fabric`

- `MCMTFabric implements DedicatedServerModInitializer`: load config, call
  `SerDesRegistry.init()`, register commands through
  `CommandRegistrationCallback`, start the thread pool on
  `ServerLifecycleEvents.SERVER_STARTING`, shut it down on `SERVER_STOPPED`.
- `fabric.mod.json`: `environment: "server"`, depends on `fabric-api` (command
  and lifecycle modules only) and `minecraft ~1.21.1`.
- `jmt_mcmt.mixins.json` from `common` is referenced from the Fabric jar; the
  common classes are shaded into the Fabric jar at build time.

### `neoforge`

- `@Mod("jmt_mcmt") MCMTNeoForge`: register `ModConfigSpec`, call
  `SerDesRegistry.init()`, listen to `RegisterCommandsEvent`,
  `ServerStartingEvent`, `ServerStoppedEvent`.
- `neoforge.mods.toml` generated from a template with the NeoForge version
  range filled in from `gradle.properties` (same idea as today's
  `generateModToml` task).
- Mixin config declared in the jar manifest / `neoforge.mods.toml` `[[mixins]]`.

## 7. Testing

### Unit tests (`common/src/test`)

JUnit 5. Cover `ConcurrentDoublyLinkedList`, `ConcurrentLinkedList`,
`ChunkLock` (lock ordering and reentrancy, no deadlock when two threads lock
overlapping radii), `SerDesRegistry` lookup (whitelist beats target, default
filter fallback), `MCMTConfig.getParallelism()` for all three modes.

### Smoke tests (`tests/smoke`)

A script (`run-smoke.ps1` and `run-smoke.sh`, same behaviour) that for a given
loader:

1. Builds the jar and sets up a fresh `run/<loader>/` directory with
   `eula.txt=true`, `server.properties` (offline, no GUI, small view distance,
   `spawn-protection=0`), and the mod jar.
2. Starts the dedicated server with the loader's launcher, stdin attached.
3. Waits for the "Done" line, then sends a scripted command sequence:
   `forceload add` a 5x5 chunk area, `summon` 200 mixed mobs and item entities
   in that area, place ticking block entities (hoppers, furnaces) with
   `setblock`, run `mcmt stats`, let it tick for a configurable duration
   (default 120 s), run `mcmt stats` again, then `stop`.
4. Fails if: the server does not reach "Done" within 5 minutes, any
   `Exception`/`Error` stack trace is logged (allowlist for known-harmless
   lines), the watchdog fires, `stop` does not exit within 60 s, or `mcmt
   stats` reports zero parallel tasks executed while the feature is enabled.
5. Writes `tests/smoke/out/<loader>-report.txt` with the verdict and the
   relevant log excerpts.

The same script runs in GitHub Actions on every push to `1.21.1` for both
loaders. Each implementation phase ends with the smoke test passing on both.

### Manual validation (maintainer)

Real multiplayer sessions and modpack compatibility are outside automation and
are checked by the maintainer at the end of each phase.

## 8. Automation (branch split and release)

Workflow `split-loader-branches.yml`, triggered on push to `1.21.1`:

1. Build both jars, run smoke tests.
2. For each loader, `tools/split-loader-branch.sh` creates a tree containing
   `common/`, `<loader>/`, `buildSrc/`, root Gradle files trimmed to that
   loader, tests, docs, `LICENCE`, and a README noting the branch is
   generated, and force-pushes it as a single snapshot commit (naming the
   source commit) to `1.21.1-<loader>`. (Amended during implementation:
   snapshots instead of `git subtree split` history; simpler, and the
   branches are read-only anyway.)
3. Upload both jars as workflow artifacts.

Workflow `release.yml`, triggered on tag `v*-1.21.1`: builds, runs smoke tests,
creates a GitHub release with `jmt_mcmt-1.21.1-fabric-<ver>.jar` and
`jmt_mcmt-1.21.1-neoforge-<ver>.jar`.

## 9. Error handling and safety

- Every hook has a disable flag and the global `disabled` flag; when disabled
  the hook calls the vanilla code path directly.
- If a parallel task throws, the exception is logged with the task description
  and rethrown on the server thread at `postTick` so the crash report is
  produced by vanilla with the MCMT section attached.
- The crash report section lists all config flags and, when `opsTracing` is
  on, the tasks running at the time of the crash.
- The warning log line every ~3 minutes that MCMT is installed and logs may
  be misleading is kept.

## 10. Implementation phases

1. Skeleton: multiloader build, both jars start a dedicated server, config
   loads, `/mcmt` commands respond, unit tests and smoke test harness run in
   CI. No parallelism yet.
2. World and entity parallelism: `MinecraftServerMixin`, `ServerLevelMixin`,
   `UtilMixin`, server-thread patch, SerDes registry wired in.
3. Block entity and environment ticks: `LevelMixin`, `ServerChunkCacheMixin`
   (tickChunks part), `SynchronisePlugin`, `ClassInstanceMultiMapMixin`.
4. Chunk provider cache and collection replacement (former `sync-fu` scope).
5. Branch split automation, release workflow, `master` landing page, README
   and changelog.

Each phase is one or more commits on `1.21.1` and ends with green unit and
smoke tests on both loaders.
